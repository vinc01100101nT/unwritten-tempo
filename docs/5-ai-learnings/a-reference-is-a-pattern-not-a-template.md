# A Reference Is a Pattern, Not a Template

**Reach for this when:** the user says "use X as reference" for designing something new — a roster, a screen, a
set of items — or replies that your design is "just a copy of X".

## The rule

"Use X as a reference" means take X's **rules and structure** — its counts, its proportions, its pricing, how its
parts depend on each other — and invent the **content** fresh from the new thing's own identity. Before presenting,
hold every new item up against X and ask "is this the same mechanism with a new name?" Any item that is goes back
to the drawing board, not into the list.

## Why

Asked to plan the Bow's skills "with the Sword's skills as reference for patterns such as skill counts", the first
proposal re-skinned the Sword nearly one for one: a stack-on-every-basic-attack passive cashed by a big ultimate
(the Sword's Rising Breeze and Last Petal), a dance of hops around a star (Thousand Petals), add-stacks-on-kill
(Second Bloom), and range charges after casting a dash (Crossed Branches). It cost a whole design round, and the
user had to point out the copying.

The trap is that copying feels like following the instruction: the reference is the only worked example on the
table, so its mechanisms are the first ones that come to mind, and each one is easy to justify on its own.

## How to apply

1. Before designing anything, write down what you are taking from the reference — its numbers and its structure —
   and stop there.
2. Design each item from the new thing's own identity sentence first. Reach for the reference only to check counts
   and prices.
3. Before sending, put the reference's list beside yours and compare them row by row. If the trigger and the payoff
   both match a reference item, it is a copy, even with a different number or stat.
4. Where a mirror is deliberate (the same engine moment used in the opposite direction), say so in one line, so the
   user can veto it.
