Before showing a skill pool, layout or design list, run my own audit on it first: two skills doing the same job, a part that does nothing (a knob with no effect, a mechanic its own build can never trigger), and a promise that reads nothing. Fix what I find, then present.

**Why:** 2026-10-22, Staff orb pool v5 — the user had to ask "check your skills for redundancy and dead effects. always check yourself before suggesting. so we dont waste tokens". The audit then found four spreaders doing one job, an Earth ultimate whose freeze-shatter could never fire in a pure-Earth build, and a projectile-speed knob that changed nothing. Each round they find it costs a full reply.

**How to apply:** for every skill ask (1) does another skill already do this job? (2) does every part change something real? (3) can the build that maxes it actually trigger its main mechanic? Then for the pool: count how many skills do each job (spread, cash-in, shatter, chill) — more than two of the same is a redundancy. Related: [[the-five-anti-invention]].
