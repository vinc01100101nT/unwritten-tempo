**Built 2026-09-25.** `Assets/3_Data/Recipes/BiomeTable.asset` (class `Scripts/Editor/BiomeTable.cs`) is the one
place the map generator reads a biome's look from: `baseTile`, `patchTile`, `roadTile` (empty = the recipe's own
`pathTile`), `tint`, `patchAmount` (<0 = recipe's `dirtAmount`),
and `props` = which prefabs a `PropCategory` means in that biome (category absent = whole pack list; listed with no
prefabs = places nothing). It replaced the coded `RecipeGenerator.BiomeOf` switch; a missing table/row/tile fails the
bake with a dialog, never a silent fallback.

- **Adding a biome:** one table row + append its name to the END of `Biome` (inserting mid-list remaps every saved
  creature's biome — see [[biome-none-agnostic]]).
- **Proof it moved values unchanged:** Grassland and Snow maps generated with seed 4242 before/after were identical
  (735 scene objects, same ground mesh/material/sidecar).
- **Forest (2026-09-25):** mud base, leaf-litter patches (patchAmount 0.9 ≈ 33–44% leaves), soil road; Flowers =
  ferns/mushrooms/bush, Landmarks = tree stumps. No creature has biome Forest yet.
- **Field template (FieldRecipe.asset) changed the same day, affecting every field map generated after:** trees
  Scatter over the whole map (were an EdgeRing), grass uses the new `PlacementRule.Clumps` (bunches of touching
  2.5 m cells; 50 bunches ≤24 cells, 18 tries/cell, spacing 0.2, scale 1.3 → ~75% cover, ~11 plants/cell, ~5k
  plants on a 60 m map — frame cost NOT measured).
- **All 14 biomes built 2026-09-25:** Highland, Peaks, Steppe, Coast, Swamp, Sacred, Haunted, Mist appended after
  Forest; Snow/Desert/Volcanic/Corrupted moved onto their own tiles, tint white. Every non-Grassland/Forest row lists
  all five field-template categories (Landmarks, Trees, Rocks, Flowers, Grass), empty = places nothing. Grassland +
  Forest proven identical before/after (seed 4242, scene lines equal once random fileIDs are masked).
- **Test maps:** a 15-map chain `test_grassland_cliffs` (w14) ↔ `test_grassland` ↔ `test_forest_a` ↔ `test_highland` … ↔ `test_corrupted` (test_forest_b deleted 2026-09-25 at the user's word), 60 m each,
  W/E doors (`Portal_w{k}_to_*`; test_grassland's link is w13), each with a copy of test_forest_a's WorldSpawns row (test_grassland's asks for biome Grassland). Not walked in game yet.
- **Ground levels (2026-09-27):** row fields `bumpHeight`/`bumpWidth`/`bumpLevels`/`bumpSteepestDegrees`; >0 → `GroundBumps.Make` heights + a MeshCollider on the ground mesh instead of the flat box. Levels ≥2: noise ranked to equal shares, then terraced (half of each band flat, half a smoothstep rise). Slopes: shaped on a 4× finer grid (`GroundBumps.Fine`), `LimitSlope` lowers high points to a max-slope cone over 16 neighbours (near-circular ramps), then `Soften` blurs creases σ0.5 m (`EdgeRounding`) before reading back the vertices — so level edges curve instead of zigzagging on the 0.8 m grid (2026-09-27, [[water-reflection-quantized-plane-bug]]); widening/flattening the whole shape was tried and failed. Grassland = 1.2 / 16 / 3 / 20° (user: "higher and lower ground should be obvious", then "ignore the mobs walking limit for now, make the slope greater than 5 degree"), pinned in check-biome-table.py. Creatures route over these slopes by the one walking rule ([[one-walking-rule]]). test_grassland rebuilt (doors w13 east, w14 west re-added); on cliff maps the shape goes on the cliff TOPS (`topRise`), the pass floor is flat.
- **Cliffs (2026-09-27):** on/off = `BiomeRow.cliffs` (on: Highland, Peaks, Coast, Volcanic, Haunted, Corrupted — the user took the handoff's plan 2026-09-27; every row's shape numbers are in docs/3-world/biomes.md) unless `MapRecipe.cliffs` (`CliffChoice` FollowBiome/On/Off) overrides; numbers from the recipe (`cliffHeight`/`cliffPassWidth`/`cliffMeetingPoints`, field template 1.5/8/3; town/dungeon recipes Off) → `GroundCliffs.Spec` holds a 0.25-grid field = max(distance-to-road − pass/2 − wander ±0.8, 1.5-in map-edge rock), Gaussian-blurred σ1.2 (rounded corners, closed pass ends). Since 2026-09-30 the cliff IS the ground (RULE ONEGROUND): `GroundCliffs.BuildGround` lays floor, foot, face, shoulder and top as ONE mesh + ONE MeshCollider. Cut line = field value `Cut` 0.3; ground squares crossed by it are split along it (marching squares, saddles by the square's middle), and the face is stitched between a low and a high copy of each crossing point, rows shared by both squares on that edge. Low side = floor + a quarter-circle foot from f=-foot to the cut; high side = shoulder quarter-circle then rim rolling over `RimRoll`; the rock is paint (GroundBlend `_CLIFF_ROCK`, uv1.x) on the one material `Ground_<map>_cliff.mat`, shadows On. Measured on all 17 cliff maps: 0 holes, 0 stacked walkable spots, 0 face triangles turned the wrong way. Meeting points (`MapRecipe.cliffMeetingPoints`, the user's "cliff-end meeting point of low and high ground"): `Spec.Standing(x,z)` 0 within 1.5u of a spot -> 1 by 10u; scales cliff height, carving and rim; spots picked on road-side wall-line crossings of the field, >=15u apart, >=6u from the edge. Walk-up measured 22.7-25.6 deg. Maps: test_grassland_cliffs (seed 707456464, 1.5 / 8 / 3 meeting points, exits +-26,0; its door is re-added after every rebuild) + the 16 world fields of the cliff biomes. Face colour = `BiomeRow.cliffFaceColor` (alpha 0 = unset → gravel_scree tile) → `GroundCliffs.Spec.faceColor` → `_CliffFaceColor` in GroundBlend, which multiplies the rock map; with a colour, `MakeCliffMaterial` also turns on `_CLIFF_FACE_COLOR`, which skips the map and shades the colour itself from `uv1.y` (0 foot → 1 top, written by `GroundCliffs`): lighter up, greyer at the foot, 3D value-noise patches (no painted horizontal lines — evenly spaced ones were tried and the user rejected them: "cliffs in real life do not have them"), cracks = 3D cell (Voronoi F2−F1) borders scaled (1.1, 0.5, 1.1), masked into lengths (isolines of value noise were tried first: they drew closed loops that looked doodled). Carving (2026-09-27): face stands back (0.4 + columns + quantised blocks ~1–2 m × 0.5 m) and 0.45 m ledges once a metre jut forward to 0.15 of that, broken by noise; going up a profile the recess may grow by at most one row's height ÷ tan 50° (`FaceSteepestLeanDegrees`) — without it the blocks and ledges made walkable <45° shelves and the player walked up the face (replay: a 0.5×0.15 capsule pushed into the cliff from 275 pass spots × 8 directions climbed onto rock from 2 spots on the original face (a meeting point), 25 with blocks, 40 with ledges, back to the same 2 with the cap); max still `Recess` 0.7. Rounded foot (user: "ground must transition smoothly and rounded to the face"): `FootRadius` 0.5 × standing, ≤ 0.3 × cliff height, min 0.02, drawn by the ground's own points in front of the cut; carving eases in above it and out below the shoulder. `InCliffBand` = d > −0.5 (= −FootRadius) and d < `PropClearBehind` (the exact old distance, kept so rebuilt maps place props where they were); widening it to −1.0 cost 915 of 2557 props on the test map. Colours (2026-09-28, the user: "apply to other biomes and the whole world"): each = linear-light average of the biome's own earthy/rocky tile — Grassland #604623 soil (pinned), Highland + Peaks #7B7C7E gravel_scree, Coast #A1958B pebbles, Volcanic #3D3738 cooled_lava, Haunted #41362D grave_dirt, Corrupted #2C2731 blighted_soil. The 16 cliff-biome fields were rebuilt 2026-09-28 with `BuildCore` keeping every other map: doors, arrivals, props and ground byte-identical, only scene + cliffs mesh + cliff material changed.
- **Building without touching the user's editor:** `RecipeGenerator.Generate(r, exits, mapPicksRoad, leaveOpen:false)`
  saves and CLOSES the new map and restores the active scene (refuses if that map is open). Wire doors by opening
  additively + SetActiveScene first (else MakePortal's objects land in the user's scene), save, close. `unity cmd eval`
  answers "timed out after 5000ms" on long builds but the build keeps running — write progress to a file and poll.
- **Every row patchAmount 0.9 except Volcanic 0.5** (thin lava glow) (user, 2026-09-25: the recipe's own 0.18 painted "one cell in a zone"). Each
  `BiomeProps` entry has `countMultiplier` (× the recipe's count for that category; 1 = as-is; applies only when the
  pool came from the biome's list). Values + reasons live in docs/3-world/biomes.md "How many of each". Snow now uses
  frozen_dirt patches + gravel_scree road (ice at 0.9 read as a frozen lake); Steppe grass = Rye only; Haunted and
  Corrupted Trees = the two stumps. Forest re-proven identical after the multiplier code.
- **Weather a biome always has (runtime, 2026-09-25):** `Resources/BiomeWeather.asset` (class `BiomeWeather`) — per
  biome `alwaysPuddles` / `alwaysSnowCover` 0..1; Swamp puddles 1, Snow blanket 1, Mist fog 0.6 (`alwaysFog`, read by FogOverlay). `WetGround`/`SnowGround` show
  `max(weather, held)`; held puddles draw on EVERY tier (rain puddles stay High-only). The map's biome comes from a
  `MapBiome` marker the generator stamps into each map (`MapBiome.Current`); old maps have none → nothing held.
  SnowGround snaps its blanket on a map change. The editor-only BiomeTable can't hold these (runtime can't read it).
