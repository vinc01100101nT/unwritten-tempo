Wall authoring across `tools/map-painter/index.html` (paint) + `unity/.../Editor/MapPainterImporter.cs` `AutotileWalls` (bake). Cells classified from neighbours (`WallKind`/`wallKindAt`): `x`/`z` orthogonal straight, `ne`/`nw` 45° diagonal (needs NO orthogonal neighbour + one opposite diagonal pair), else `tower`. Tower facing = **vector sum of unit dirs toward wall neighbours, faced AWAY (outward)** — wrap-safe, never `(a+b)/2`; N+E corner → 45°; verified truth table. Per-stroke settings (`wall`/`tower` piece + `thickness`) stamped on each wall cell in map.json objects. Diagonal walls are painted with the 📏 Line tool on the Wall brush (`applyLineWall` uses `lineCells` fulls only).

**3 bugs fixed (2026-07-18), all found by MEASURING not guessing:**
1. **Auto road→gate fired on sidewalk.** `ground_sidewalk` maps to the road/path channel (1); the old "road under wall → open a `Wall_entrance` gate" rule turned mid-run cells into gate archways, so a solid wall over paved town ground was impossible. **REMOVED** the auto-gate entirely (importer + painter `drawWallGlyph`). Gates are now deliberate-only.
2. **Pieces overlapped / z-fought.** `Wall_part2` is ~2.34u long (at WallKitScale 0.3) but diagonal cells are only √2·cellSize = 1.414u apart (cellSize=1). The scale-to-fill had `Clamp(L/segLen, 1, 2.2)` whose **min of 1 refused to shrink the piece below natural**, so each overshot its cell by ~0.93u → z-fight. **FIX:** `lenScale = s * (L/segLen)` (no min clamp) → piece spans exactly the run length → abuts (overlap 0.000). Trade-off (squash) was removed 2026-07-18, see below.

**No-squash CROP tiling (2026-07-18, replaces the squash trade-off):** `AutotileWalls` was restructured from per-cell to TWO passes — pass 1 places towers, pass 2 groups interior straight cells into maximal colinear RUNS (same kind+piece+thickness; a straight cell needs same-kind neighbours on BOTH sides to classify, so run ends are always towers) and tiles NATURAL-size pieces end-to-end along each run (`whole = floor(runLen/segLen)`), then **crops only the final leftover piece** via `SliceMeshMinSide` (Sutherland–Hodgman triangle clip along the piece's long LOCAL axis, keeping the min-side = run-start side; interpolates pos/normal/uv/tangent/colour). Sliced meshes bake to `Assets/2_Generated/Meshes/WallSlices/{map}_{piece}_{x|z}_{frac‰}.asset` (namespaced per map, cleared each bake by `ClearMapSlices`), assigned to BOTH MeshFilter + MeshCollider of the scene instance. **The source prefab's mesh is NEVER touched** — only regenerable baked copies. `SeatStraight`/ext-reach logic replaced by `SeatWallSegment` (natural scale, no long-axis stretch; centre = segment midpoint). Bricks now keep true density, seams tuck under towers, no squash. `MapPainterImporter.cs`.

**PASS 3 — adjacent-tower LINK (2026-07-18):** two towers touching edge-to-edge have no straight cell between them (a 2-cell wall, an L-corner, a T/X junction), so pass 2 never fills the gap → bare posts with a hole. Pass 3 scans each tower's +E/+S neighbour (each unordered pair once); if it's also a tower, `LayRun` drops a wall piece spanning the two tower CENTRES (length = cellSize, cropped to fit, both ends tucked inside the towers). The tile+crop body was extracted into a local `LayRun(piece,thick,segLen,axisX,yaw,sx,sz,ux,uz,runLen)` shared by pass 2 and pass 3. No overlap-cut needed: links meet straight runs at the shared tower centre. Only orthogonal adjacency is linked (diagonal-corner towers aren't).

**TOWER-FACING (STILL BROKEN — reverted 2026-07-18, see `handoffs/tower-facing.md`):** end tower with one wall (beside another tower) faces off-axis, and corners don't read as 45°. Tried 3 fixes — (1) exclude `WallKind=="tower"` neighbours, (2) `AttachedWall` "wall physically enters tower" rule, (3) snap 2-wall corners to nearest diagonal — user reported STILL wrong each time, so all 3 were REVERTED to the original vector-sum `TowerYaw`. Durable lesson that IS proven: parse the baked scene against the json replayed on the IMPORTER'S z-FLIPPED grid (`cz = floor(sizeZ - o.z)` — MUST flip or every cell is mirrored) — that confirmed baked==formula (bake was NOT stale). Root cause of why the "correct-looking" formulas still looked wrong in-scene is UNRESOLVED — likely a facing-convention / z-flip-vs-yaw mismatch the offline replay can't see. Don't trust prior "it works" reasoning.

**GAP-at-tower gotcha (fixed same day):** the first crop rewrite ended each run at the tower CELL's near edge (half a step out), but a tower sits at its cell CENTRE and is smaller than a cell → a visible gap between wall and tower. Fix: when a run end abuts a `WallKind=="tower"` neighbour, reach an EXTRA half-step (`startExtra`/`endExtra` = step*0.5) so the run reaches the tower's centre and the crop-seam hides INSIDE the tower; free (non-tower) ends stay at the cell edge. Interior-of-run cells still classify as straight even next to a tower because `WallKind` tests cell PRESENCE not kind, so run ends are the cells with only one same-axis neighbour and the flanking tower is one cell further out.
3. GOTCHA: `Measure()`/manifest `footprint` are already at the prefab's **authored scale** (post tree-fix), NOT native ×1 — don't multiply by baseScale again when reasoning about `segLen`.

**Diagnosis method that cracked it (ground truth, no Unity needed):** replay `WallKind` on `map.json`/`prontera.json` in node (with the importer z-flip `o.z = sizeZ - o.z`); read the baked `lastline.unity` — split on `^--- `, find `PrefabInstance` blocks whose `m_SourcePrefab` guid = the wall prefab, parse `m_Modifications` (propertyPath→value) for position/scale/rotation; read `Editor.log` (`%LOCALAPPDATA%/Unity/Editor/Editor.log`) for compile errors + the `[unwritten] Merged into…` piece counts; compile-check editor C# offline via `dotnet` with stubbed UnityEngine types (Vector3 needs `operator *`).
