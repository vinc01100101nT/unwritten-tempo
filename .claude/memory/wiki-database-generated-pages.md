Built 2026-09-26 at the user's request ("live, from a single source of truth, no stale").

- **Pages → files → writer:** Monsters = `monsters.generated.json` (`MobExport`); Skills = `skills.generated.json`
  (`SkillExport`); Equipment + Materials (incl. Trademark weapons, Armor variants) = `items.generated.json`
  (`ItemExport`); World Map = `world.generated.json` + `wiki/assets/world-map.png` + `wiki/assets/minimaps/*.jpg`
  (`WorldMapExport`); Elements = `elements.generated.json` (`ElementExport`). Every value comes from the game's own
  function (MonsterDefStats, CreatureDrops.Line/WhoDrops, WorldSpawns.HomesOf, Trademarks.ChanceOf,
  ItemTooltip.TrademarkLines, ArmourWords.Describe, Elements.Modifier, SkillTooltip).
- **ONE trigger hub: `WikiExport`.** Any change re-runs EVERY export (pages depend on each other's sources): asset
  save/import/move/delete under Resources/Monsters, Items, Skills, WorldMap, or WorldSpawns/WorldAtlas/WeaponColors;
  every recompile; the world layout json (FileSystemWatcher). Play-mode changes wait for Play to end. It clears the
  catalog caches first (MonsterCatalog, SkillCatalog, ItemCatalog.Reload, MaterialCatalog.Forget).
- **Runs from `EditorApplication.update`, NOT delayCall** — measured 2026-09-26: a background editor kept updating
  while its delayCall queue sat unrun for minutes. Proven after the switch: asset change → file rewritten in ~2 s,
  layout touch → ~4 s, recompile → ~6 s, all with the editor unfocused.
- Previews: one map re-renders when its scene is saved (also from update); the menu re-renders all 76 (~5 s).
  14 special maps have no scene yet and sit below the painted picture.
- **Browser side:** a page reads the generated files fresh on each visit, and NOTHING polls. The user rejected a
  5-second re-read on 2026-09-26 as too expensive: "we just need to update the wiki when the data changes".
- **The website shows a copy.** The editor rewrites the files in the repo; the website serves the copy publishing made,
  so a change shows only after `tools/publish-update.py --site-only`. The old standalone wiki page was deleted on
  2026-10-04 — the main website is the only page that draws these files.

**Why:** the user wants wiki data that can never lag the game.
**How to apply:** a new Database page = a new export called from `WikiExport.RunAll`, and its asset folder added to
the hub's watcher if it reads a new one. Never add a per-export trigger. See [[mob-item-map-data-tables]].
