Whenever I write a plan (a planning doc, a plan in chat, or a planner's output I relay), each item gets four
parts, in this order: **the issue**, **why it is an issue**, **the fix I recommend**, **the expected result after
the fix**.

**Why:** the user asked for it on 2026-10-02 after reading the live-readiness plan, which was laid out as
"where it stands / steps / stays the same / proof" — it described the work without saying plainly why each
problem mattered or what would be true afterwards.

**How to apply:** use those four as the headings or labels for every item. Supporting detail (what stays the same,
rollout, proof) goes inside "the fix" or "the expected result", never as extra top-level parts. When briefing a
planner sub-agent, ask for this shape in its report. Related: [[the-five-anti-invention]].
