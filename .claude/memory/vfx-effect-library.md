Built 2026-07-01. Data-driven particle-effect integration layer so skills/buffs/hits spawn animated prefabs **by stable id**, never by hardcoded prefab ref. Mirrors [[mob-item-map-data-tables]] (MonsterCatalog) + [[perf-runtime-hotpath-patterns]] pooling.

**Files (unity/Assets/Scripts/):**
- `EffectLibrary.cs` — `EffectDef` (id, prefab, scale, lifetime) + `EffectLibrary` ScriptableObject; asset at `Resources/EffectLibrary.asset`.
- `EffectCatalog.cs` — static load-once cache, `Get(id)`/`Has(id)`; call `Reload()` after rebuild.
- `Vfx.cs` — the spawn API (sibling of `Sfx`). `Vfx.PlayAt(id, pos[, rot, scaleMult])` one-shot; `Vfx.PlayAt(id, pos[, rot], VfxParams)` for per-spawn **scale + speed + tint** overrides (`Vfx.VfxParams` struct; zero-default fields = "unset" → authored value; `VfxParams.Scaled(x)` helper); `Vfx.Attach(id, transform, offset, scaleMult)` returns an `EffectHandle` for looping auras/shields (call `.Stop()`); `Vfx.Prewarm(id, count)`. **Reuse-safe:** `EffectHandle.Prepare` caches authored simulationSpeed + startColor per system; every `Begin` RESETS from those baselines then applies speed/tint, so a crit's params never leak into the next pooled reuse. speedMult also shortens the auto-return timer. Tint multiplies startColor (Color/TwoColors modes; authored gradients left as-is). **POOLED per prefab** (Dict<prefabInstanceID, Stack>), auto-returns when the ParticleSystem finishes (loop detected from `main.loop`); components cached once per instance in `Prepare` (no GetComponents on spawn/frame). Attached effects TRACK the target in LateUpdate (don't parent — avoids inheriting billboard breathe-scale, same reason as `GuardShieldFX`).

**Per-effect tuning = the library asset is the single source of truth.** Each `EffectDef` holds `scale` + `offset` (Vector3 world nudge) + `lifetime` (0=auto); `Vfx.PlayAt` applies all three so one number fixes an effect everywhere. TWO tuners: (1) editor `Tools ▸ unwritten ▸ Art ▸ Effect Preview` (`Editor/EffectPreviewWindow.cs`, pri 625) — spawns in an empty scene view (no size reference — user found this hard). (2) **PREFERRED: in-Play `EffectTuner` (`EffectTuner.cs`, press F8)** — self-bootstraps in editor/dev builds via `[RuntimeInitializeOnLoadMethod]`+DontDestroyOnLoad (same pattern as DevSettings), IMGUI overlay: filter+list all ids, Scale/Offset(xyz)/Lifetime sliders, **Spawn on Player / Spawn on Mob** (nearest via `MonsterAI3D.Active`, player via `FindFirstObjectByType<Player3DController>`), SAVE persists to the asset (editor Play asset-edits survive Stop; wrapped `#if UNITY_EDITOR`). Working values pushed into the live def before each spawn → WYSIWYG. This solves "can't judge size without real mobs/players." Both write the same `EffectDef` scale/offset/lifetime. `EffectLibraryBuilder.RebuildCore()` is the dialog-free build (bridge/headless); `Rebuild()` menu wraps it + dialog. Library already built = **88 effects**. `hit.holy` default set to scale 0.3 / offset (0,0.3,0) / lifetime 0.9.

⚠️ ONE-SHOT LOOPING FIX (2026-07-01): a `PlayAt` one-shot whose prefab has a LOOPING sub-emitter (e.g. Holy hit's halo) never ended — `Begin` used to set `returnAt=0` for any looping systems. Fix = thread a `oneShot` flag: `PlayAt`→oneShot=true is ALWAYS time-bounded (`oneShotDuration/speed`, or `lifetime` override); only `Attach`(oneShot=false) waits for `Stop()`. At the timer a one-shot-with-loop calls `Stop()` (stop-emit + fade tail via `stopping` flag) then `Return()`, avoiding a hard cut. Symptom was "effect keeps playing after attack done + too big".

**Editor tool:** `Tools ▸ unwritten ▸ Art ▸ Rebuild Effect Library` (`Editor/EffectLibraryBuilder.cs`, priority 624) — scans a `Roots[]` array of packs: `Magic effects pack/Prefabs` (nested-by-category, prefix from subfolder) + `Procedural fire/Prefabs` (flat, fixed prefix `fire`). ids = prefix + kebab name (`Hits and explosions/Explosion` → `hit.explosion`; `Procedural fire/…/Explosion` → `fire.explosion`; prefixes: aoe/aura/env/hit/circle/shield/portal/slash/smoke/spark/fire). Add a pack = one `ScanRoot` entry (fixedPrefix = flat, null = per-category map). Idempotent + non-destructive: keeps existing entries matched **by prefab ref** (so renamed ids + hand-tuned scale/lifetime survive), only adds new, reports deleted. Pops a modal dialog → let the USER click it.

⚠️ URP PINK-SHADER GOTCHA (Procedural fire, fixed 2026-07-01): the pack's `.shader` `EGA/Particles/FireSphere` is a **built-in-RP** shader (`CGPROGRAM`, no URP pass) → renders MAGENTA in our URP project (in EDIT mode, not just builds). Fix = repoint its 4 materials (FireSphere1/FireSphere2/SparkSphere/Trail67) to the pack's URP twin `Shader Graphs/FireSphere` (`.shadergraph`, `UniversalTarget`). Same reference names (`_MainTex`/`_Color`/`_Emission`/`_Frequency`…) so textures+tuning carry over on `material.shader = graph`. The pack's "How to change rendering pipeline.png" note was signalling exactly this. RULE: any imported vendor FX pack that ships both a `.shader` and a `.shadergraph` twin → materials must use the shadergraph under URP or they're pink. Always-Included-Shaders (Graphics settings) is a separate BUILD-strip fix, NOT the pink cause.
