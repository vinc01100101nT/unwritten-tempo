On **unwritten** (Unity 2D), smart pathfinding shipped **2026-06-14** (supersedes the old "deferred / line-of-sight only" plan). Architecture:

- **`Pathfinder.cs`** — static, dependency-free grid A* over the live physics world. No NavMesh bake, no package, no scene object, no layer setup. `FindPath(from, to, agentRadius)` returns string-pulled world waypoints (or null → caller falls back to straight line). **Wall rule (`IsWall`): a non-trigger collider blocks UNLESS its `Rigidbody2D` is `Dynamic`.** ⚠️ Do NOT use `attachedRigidbody == null` — that wrongly ignored Tilemap/Composite colliders (Unity backs them with a *Static* Rigidbody2D), so units pathed straight through hand-painted trees and got stuck (the 2026-06-14 "mobs stuck at tree" bug). So: plain static colliders + static-body tilemap/composite = walls; triggers + dynamic units = not walls. Open ground = straight line (A* only when LOS blocked). Tunables: `CellSize` (0.5), `MaxExpansions` (6000), `ObstacleMask`.
- **`PathAgent.cs`** — the attachable "smart movement" component (the "component to attach" the user expected). Drop on ANY moving unit (player/monster/ally; NOT static NPCs). API mirrors `PlayerController2D`: `MoveTo` / `MoveToward` (repaths on a cadence) / `Halt` / `Arrived` / `Facing`. Self-steps the Rigidbody2D via MovePosition. **Units do NOT block A*** (you must be able to reach a unit you chase/attack); instead PathAgent does **soft local avoidance** — `Separation()` gently steers around other *dynamic* units while moving (Dota-style, no stacking). `avoidIgnore` (Transform) is set by the brain to the current target so melee still lands: MonsterAI → player; PlayerCommander → attack/follow target, null for plain moves. Tunables: `avoidRadius` (0.6), `avoidStrength` (0.6), `agentRadius` (player 0.4 / monster 0.35).

**Integration (no churn to `PlayerCommander`):** `PlayerController2D` now delegates `MoveTo/MoveToward/Halt/Arrived/Facing` to a sibling `PathAgent` (auto-added in `Start`, inherits its speed/arriveRadius); if no agent it still works as the old straight-line mover. `MonsterAI` is now a **pure brain** (senses/aggro/leash/touch-damage) that issues `PathAgent` orders; it `[RequireComponent]`s + auto-adds a PathAgent so old monster prefabs gain routing without a rebuild. `PlayerController2D` stays the canonical "this is the player" marker — keep it ON the player, never on monsters.

**Editor wiring:** `PathAgent` added by `PlayerBuilder`, `MonsterBuilder.BuildMonster`, `MonsterBuilder.EnsurePlayerCombat` (= **Setup Mouse Combat** / Run All), and `Bootstrap`. Existing scene player auto-routes on Play; re-run Setup Mouse Combat to make the component Inspector-visible.

**⚠️ HARD-WON GOTCHA (cost a long debug session 2026-06-14):** a Dynamic `Rigidbody2D` moved ONLY by `MovePosition` (no `linearVelocity` build-up) gets put to **sleep** by Unity once it briefly stops — and **a sleeping body silently IGNORES `MovePosition`**, so the unit freezes mid-route in open space and never wakes. Symptoms were monsters/player "stuck" with totally normal state (`body=Dynamic, simulated=True, constraints=FreezeRotation, timeScale=1`). Fix: `PathAgent.Awake` sets `rb.sleepMode = RigidbodySleepMode2D.NeverSleep`. This is set in CODE (not serialized), so it applies to all existing units at Play without rebuilding prefabs. The old straight-line `MonsterAI` never hit it because it never really stopped; pathfinding added genuine stops (arrive/halt/stop-distance) which let bodies sleep. ANY future `MovePosition`-based mover needs NeverSleep.

Validated working 2026-06-14: monsters move, chase, and route around the house/tree.

**Crowd / collision model (2026-06-14, user-approved):** hordes use the Diablo/Ragnarok soft-crowd model, NOT hard physics collision (which jams + jitters when many converge on one target). Specifics: (1) monsters share physics **layer 8** with self-collision disabled (`Physics2D.IgnoreLayerCollision(8,8,true)` in `MonsterAI.Awake`) so a pack passes THROUGH each other; (2) `PathAgent.Steer` does radial separation + **tangential slide** (Dota "Short Pather") so they fan out / surround instead of conga-lining; (3) `PathAgent` has **turn-rate damping** (`turnSpeed`, deg/s) so conflicting avoidance can't spin a unit in place — BUT damping + avoidance are SKIPPED on the final `stopOnArrive` step, else the unit orbits the click point; (4) each monster calls `Physics2D.IgnoreCollision(monsterCol, playerCol, true)` in `MonsterAI.Start` so **mobs never physically push the player** (they still surround + deal distance-based touch damage). Monster avoidance tuned in `MonsterAI.Start` (`avoidStrength 0.9`, `avoidRadius 0.8`). ⚠️ Layer 8 assumes it's an unused user layer; if the project later names/uses layer 8, pick another index. User considered full RVO/ORCA (solid mobs, no overlap) but chose to keep the soft-crowd model.

**Player drift fix (2026-06-14):** crowd avoidance (`Steer`) is a MOB-only behaviour. It must stay OFF on the player — `PlayerController2D.Start` sets `agent.avoidRadius = 0f`. Symptom when left on: the player visibly *drifts/curves* past a swarm instead of going straight to the clicked point, because nearby mobs steer its heading (worst on routed multi-waypoint moves; `Steer` is skipped only on the final `stopOnArrive` segment). The player is directly user-commanded → it should ignore mobs entirely for movement (it already passes through them and they can't push it). Don't re-enable player avoidance to "make it dodge mobs" — that IS the drift.

**How to apply:** auto-combat (auto-walk to target) and any future ally/companion brain (CompanionAI) should REUSE `PathAgent` — don't write new routing. Dota-style hybrid confirmed (user research): our grid A* = their "Long Pather", our `Separation` = their "Short Pather" wall-tracing; turn-rate dampening is unimplemented polish.
