**⭐⭐⭐ CHARACTER-RENDER COMMIT (2026-07-04) — read FIRST; supersedes "characters stay billboards" everywhere below.** The **PLAYER and NPCs are now LIVE-3D skinned characters** (Quaternius bodies rigged to **Mixamo Humanoid** via the batch API pipeline — see [[mixamo-batch-autorig-api]]). **MOBS stay billboards** (`BakedBillboard8`/`SpriteBaker8`/`BatchCharacterBaker` untouched). The 3D player path graduated from spike → the real system: `Setup Systems Scene` seats a rigged model on the player via **`Player3DVisualBuilder`** (Humanoid controller = `StanceLibrary` × **`HumanoidClipResolver`** reading shared clips from `Assets/Art/Quat/Anim/Humanoid/`); model-swap = **Tools ▸ unwritten ▸ Rigs ▸ Set 3D Player Model**. **DELETED** in this commit: `BakedPlayerVisual`, `Use Baked Character`, `Use 3D Character`, `Use 3D Caster`, `Revert 3D Character`. The runtime seam is unchanged — `StanceController`→`IStancePose` still the choke point; the player sink is `Character3DPose` (+ `Character3DVisual` brain-feeder, shared `PlayerStanceBrain`). ⚠️ **REMAINING (not done):** NPC visuals still spawn billboards — `TownNPC`/`AmbientLife` were only DECOUPLED from the deleted player billboard (footstep gait now reads `Player3DController` directly); a 3D-NPC prefab pipeline + AI-driven `Character3DPose` locomotion driver is the open follow-on, blocked on the Humanoid clips being in-project.

**⭐⭐ FINAL COMMIT (2026-06-17) — read this first; supersedes the Kenney details below.** The environment art is **Just Create Studio's "Stylized Low Poly Nature" pack** (`unity/Assets/Art/LowPolySimpleNature_FBX/`, 25 FBX sharing ONE atlas), **NOT Kenney**. Its **Ground_0x meshes are artist-sculpted terrain with baked-in hills → elevation is FREE** (no procedural terrain gen). Characters stay 2D billboards (NinjaAdventure). Live scene = `Assets/Scenes/NatureStage.unity`; **Play-confirmed** (forest renders, player walks hills, paths around trees/rocks, walks through grass). Pipeline = 3 tools: `Build Prefabs ▸ Low Poly Nature` → `New Nature Stage` → `Scatter Nature` (see [[editor-tools-menu]]). User will add MORE free packs from the same artist (drop in `Assets/Art/`, add a sibling line in `KenneyPrefabBaker.BakeKit`). **The whole Kenney 3D-town pipeline + 2D-tilemap tooling was DELETED** in this commit (Town3DBaker, TerrainSandbox, HouseAssembler, `Scripts/MapGen/`, MapGenerator, FloorRuleTiles, DepthSortTools, etc.) — so the older "2D systems are KEPT, nothing deleted" note below is **no longer true**: the 2D *world-authoring* layer is gone; only rendering-agnostic gameplay (RPG/combat/UI/items/dialogue/portals) + the persistent Systems layer + `Pathfinder3D` + billboard code survive. ⚠️ SCAR: `rm -rf Shaders` also nuked `BillboardLit.shader` (restored from git); batch-delete caused a transient URP `get_scriptableRenderer IndexOutOfRange` cleared by a Unity restart.

**Decision (2026-06-16):** `unwritten` moves from the top-down **2D tilemap** game to **RO-style 2.5D** — a real 3D world (3D meshes, tilted camera, Z-buffer depth) with **2D billboard sprite** characters (the Ninja Adventure art, facing the camera). The user confirmed "commit to 2.5D" after a spike proved it works in-engine.

**Spike (committed `f195a5d` on branch `experiment/3d-world`):** `Tools ▸ unwritten ▸ Build 2.5D Spike` builds `Spike2D5.unity` — ninja billboard walking a 3D Kenney Fantasy Town under a tilted camera. New code: `Billboard.cs`, `SpikeActor.cs`, `Editor/Build25DSpike.cs`. A **3D Universal Renderer** was added to `UniversalRP.asset` alongside the 2D one (`Renderer2D` stays index 0), overridden only on the spike camera, so `main`'s 2D scenes are untouched. Kenney Fantasy Town Kit 2.0 (CC0) FBX imported at `Assets/Art/KenneyFantasyTownKit/` (FBX format only; use FBX, not GLB/OBJ).

**Ports as-is (rendering-agnostic):** Character/RPG numbers, Health, inventory/items, dialogue, HUD/UI, combat *rules*, PlayerCommander's Dota-control *intent*, the persistence model (Systems scene + additive maps), the Ninja art (now billboards), and the Phase-G skill-draft plans.

**Gets rebuilt for 3D (the spatial layer):** movement (Rigidbody2D/XY → XZ), pathfinding (**adapt the existing grid A* to XZ** — reuse `Pathfinder`'s search, swap only the 2D→3D blocked-cell check; NavMesh weighed + DECLINED, see below), depth ([[ysort-depth]] `YDepthSorter`/`DepthSortRuntime` superseded by the Z-buffer in 3D scenes), camera (`CameraFollow2D` → `CameraFollow3D` tilted follow), map authoring (tilemaps/RuleTiles/[[map-generator-tool]] → placed 3D prefabs), obstacle colliders (2D → 3D).

**2D systems are KEPT — nothing is deleted** (user has later plans for the 2D game). 2.5D is built ADDITIVELY/non-destructively: [[map-generator-tool]], [[floor-autotile-ruletiles]], [[ysort-depth]], [[pathfinding-grid-astar]] all stay on disk + on `main`; the 3D path *reuses* the grid A* core rather than retiring it. "Promote" (3D-F) = make 2.5D the default, NOT remove 2D. Keep honoring [[performance-first-prebake]] (billboards are cheap; batch static 3D, tune shadows).

**⭐ REFINEMENT (2026-06-17) — environment is 3D MESHES, not billboards.** After spiking "2D sprite-props in a 3D world" (billboard trees/houses), the user **rejected** it. Killer reason: a billboard building can't have honest collision — a collider rotating with the always-camera-facing art confuses players, a static collider mismatches the art; large/enterable structures need real geometry. **Final split: the ENVIRONMENT (ground, buildings, trees, props, terrain) = Kenney 3D mesh assets; only CHARACTERS (player/mobs/NPCs) = 2D billboards** (RO model; `Build25DSpike` already does this). Consequence: occlusion is the **Z-buffer** (billboards write depth via `BillboardLit`), so the camera-depth-vs-world-Y sprite-prop reconciliation is a non-issue — that sub-system was built then **deleted** (`Town25DConverter`, `Build25DTerraceDemo`, `CameraDepthManager`, `CameraDepthProp`, scenes `NewTown25D`/`Terrace25D`). **Kept:** `Build25DSpike` (foundation; helpers public + `BuildPlayer(foot)`/`BuildMonsters(center,r)`), height-aware `Pathfinder3D` + `Pathfinder3DConfig` (multi-level terrain on any 3D ground), `Build25DElevationSpike`, `CameraDepthSorter` + character code. **Kenney packs go in their own folder under `unity/Assets/Art/` (FBX format + colormap), beside `KenneyFantasyTownKit`.** Open: pick the Kenney-map authoring flow (hand-place / 3D generator / reskin) + stand a Kenney map under a 2.5D Systems boot.

**Phase plan:** 3D-A player (XZ move + 3D cam + billboard) → 3D-B depth+collision → 3D-C pathfinding (NavMesh) → 3D-D monsters+combat → 3D-E maps+portal travel → 3D-F promote branch to `main` once at parity (2D kept). Pathfinding DECIDED (2026-06-16): adapt the existing grid A* to XZ (reuse their proven code; NavMesh declined — it's just A* over a polygon mesh, and grid-A* gives them determinism/control for the MMO goal + reuses working code). Phase 3D-A in progress: `CameraFollow3D` + `Player3DController` (click-to-move via ground raycast + WASD + billboard anim), built by the upgraded `Build 2.5D Spike` tool.
