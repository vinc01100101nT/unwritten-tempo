**Started 2026-06-23.** A **map painter** to hand-author one map's *contents* (houses/trees/paths/walls/landmarks) as colour-coded squares — the intra-map complement to the world builder (which made the WORLD = maps + connections). Fills the gap [[recipe-generator]] can't: **exact, intentional layouts** (real street grids, a cathedral in its spot) vs procedural scatter. The two coexist: recipe = procedural bulk, painter = authored intent. Chosen over an in-Unity WYSIWYG painter because the user likes the HTML+JSON workflow (portable/reproducible) and Prop Palette already covers WYSIWYG fine-tuning.

**Design decisions (locked with the user):**
- Colours = **prefab categories** (red=houses, green=trees, yellow=path, brown=dirt, gray=wall, blue=water[no asset yet], +landmark). NOT a literal art preview.
- **Two layers:** GroundPaint brushes (path/dirt/water = paint the `ground_*` texture, NO footprint problem) vs Object brushes (house/tree/wall/landmark = placed props, the only ones with a footprint).
- **Squares are rotatable** with a facing arrow → stored as `yaw` per placement (also fixes the wall-facing guesswork from [[recipe-generator]]).
- **Size mismatch solution:** Unity exports a **prop manifest** of real measured footprints. Grid mode: 1 cell ≈ one plot; importer fits per category (1 house / scatter trees in-cell / tile wall kit across cell / multi-cell landmark stamp). Free mode: squares drawn at true relative footprints from the manifest.

**PHASES:** ① Unity backbone (DONE 2026-06-23) → ② HTML painter `tools/map-painter/index.html` (DONE 2026-06-23) → ③ Unity importer (**DONE 2026-06-23**). PIPELINE COMPLETE.

**Phase 3 — `unity/Assets/Scripts/Editor/MapPainterImporter.cs`** (`Tools ▸ unwritten ▸ World ▸ Import Painted Map…` window): pick a `map.json` (defaults to `tools/map-painter/map.json`), set scene name + prop scale (auto-reads palette `defaultScale`), **Import & Bake Scene** → `Assets/Scenes/<name>.unity` (registered in Build Settings, reopened). Thin orchestrator like RecipeGenerator: ground via the NEW `PxltgrGroundBlend.LayPlotSampled` (see below); objects seated by `PropPlacement.PlaceOnGround` (scale + yaw), grouped one node per brush, decor (`IsWalkThroughDecor`) stripped of colliders; `RegionBuilder.MakeSpawn` "Start" at origin. Reports missing prefabs / unmapped ground brushes. NOT auto-wired: trees don't sway (run `Apply Foliage Wind to Open Scene` after) and warps (use `Link Two Maps…`).
- **⚠️ COORDINATE MAPPING (locked, UPDATED 2026-06-23):** painter→Unity is a **vertical z-FLIP** (`o.z = sizeZ − o.z`, ground `cz = (rows−1) − cz`) + centre on origin (`worldX = x − sizeX/2`). This maps the painter's top row (its "north") to **+Z** (far edge) so the baked scene matches the canvas top-to-bottom. **Yaw is left untouched** — the flip's reflection and the painter's CW-from-north-on-a-y-down-canvas yaw cancel, so all 4 cardinal facings come out correct (verified). Walls autotile their own yaw (flip-immune).
- **⚠️ PREFAB FORWARD CONVENTION (fixed 2026-06-23):** the painter's facing arrow = "where I want the FRONT to point", but a mesh whose local front isn't +Z bakes rotated. Symptom: **Pxltgr houses came out 180° backwards** (they front local −Z). Fix = per-brush **`MapBrush.forwardOffset`** (degrees) added to yaw on import; `houses` brush set to **180** in `BrushPalette.asset`. Per prop-PACK, not per instance — if WoodenHouse vs House1-3 ever disagree, promote to per-prefab. Trees/landmark default 0 (symmetric/rotation-agnostic).
- **Ground refactor:** `PxltgrGroundBlend.LayPlot` was split — extracted **`LayPlotSampled(...,GroundSampler sample, grassTex, dirtTex, pathTex, stoneTex, rockTex, cell)`** (`GroundSampler = void(float wx,float wz,out Vector4 w)` where w=(road,stone,rock,dirt)=vertex .r/.g/.b/.a). The old `LayPlot` is now a thin wrapper feeding a noise+route sampler (stone/rock=0; output unchanged, RecipeGenerator untouched). Importer rasterises painted cells into per-channel weight fields, then **bilinearly** samples them per vertex (cell pitch ≈4u = the feather width) → soft edges with no tile seams.

**ENHANCEMENTS (2026-06-23, after first Prontera import):**
- **5-texture ground (stone + rock paths):** the `Unwritten/GroundBlend` shader now uses **all 4 vertex-colour channels** — grass base + `.r`=road + `.g`=stone + `.b`=rock + `.a`=dirt (was only .r/.a). So one map can mix road/stone/rock/dirt paths. Added `_StoneMap`/`_RockMap` (+tilings). Importer `GroundChannel`: path/road→.r, stone→.g, rock→.b, dirt/soil/water→.a, grass→base. Added **stone** (`ground_stones`) + **rock** (`ground_rock`) ground brushes to the palette defaults. ⚠️ existing palettes need the new **`➕ Add Missing Default Brushes`** button (idempotent merge, preserves edits) in the Brush Palette window, then re-Export Manifest — the painter then shows them automatically.
- **Wall autotiling:** wall is still an Object brush but the importer now **autotiles** it — it collects wall-brush cells (ignoring the painted prefab/yaw) and assembles the modular kit by each cell's 4-neighbour pattern (`AutotileWalls`): 2 opposite neighbours→straight (scaled to fill the cell, `cellSize/segLen` clamped ≤2.2×), corner/end/T/cross/isolated→**tower** post, and a straight cell that's ALSO a road cell→**gate** (`Wall_entrance`) — i.e. paint a road through the wall to open a gate. Pieces seat Y0, stay solid. Painter tweak: `isCellObject(b)` (id==="wall") renders walls as full-cell squares with **no facing arrow / no yaw**, so you paint a connected outline instead of fiddly individual segments. No map.json schema change (back-compat: old hand-placed wall objects re-tile fine).

**Phase 2 — `tools/map-painter/index.html`** (vanilla JS canvas, single file): fetches `./prop-manifest.json` (fallback: “Load manifest file…” button, since file:// blocks fetch — serve via `python -m http.server` in the folder). Palette auto-built from manifest brushes (object vs ground sections). Grid/Free mode toggle; **per-variant sizes** — a brush expands to a Variant strip (🎲 Random or a specific prefab); each object is drawn AND exported at its OWN prefab footprint (`objFoot` → `prefabById[o.prefab]`), so different house sizes map 1:1 to the Unity prefab (Random places a mixed-size block, each correct). White facing arrow = yaw; ground brushes paint cells at 50% alpha. Left-drag paint, right-drag erase, `R` rotate (90° grid / 15° free), wheel zoom, Space+drag pan. Exports **map.json** = `{version,name,cellSize,size{x,z},cols,rows, ground:[{brush,cx,cz}], objects:[{brush,prefab,x,z,yaw}]}` (x,z world units, origin = top-left corner; cx→+X east, cz→south/top-row=north; yaw 0=north/up CW). Import re-loads it.

**Phase 1 files (built):**
- `unity/Assets/Scripts/BrushPalette.cs` — runtime `ScriptableObject` (`Assets ▸ Create ▸ unwritten ▸ Brush Palette`). `MapBrush { id, label, colorHex, kind(Object|GroundPaint), category(PropCategory), prefabNames(List<string>), groundTex, forwardOffset(float) }` + `cellSize`(4) + `defaultScale`(0.3). **The single source of truth for brushes**; `FindByCategory` lets the recipe read it.
- `unity/Assets/Scripts/Editor/BrushPaletteWindow.cs` — **`Tools ▸ unwritten ▸ World ▸ Brush Palette…`** options window. **Create Default Palette** (7 brushes above → `Assets/BrushPalette.asset`); **🔄 Auto-fill from Props** (keyword-classifies `Assets/Prefabs/Props` into brushes — robust to NEW assets; global-excludes `ucx_`/`_lod1-3`, per-brush keyword+exclude sets, e.g. houses="house" minus door/fireplace/shutter, wall by id="wall"→wall_part/tower/corner/gate/entrance); **📤 Export Manifest** (measures each prefab's XZ footprint at `defaultScale` via `PropPlacement.TryWorldBounds`, writes `tools/map-painter/prop-manifest.json`).
- `RecipeGenerator.CategoryNames` is now **palette-aware**: reads `BrushPalette.FindByCategory(c).prefabNames` when a palette exists, else the hardcoded `CategoryNamesSeed` (fallback). `CategoryNames` + `LoadPalette` made `internal` for the window. ⇒ ONE editable prefab list (the palette wins; seed is the safety net). Cache caveat: `RecipeGenerator._palette` is cached per domain reload, so a palette created mid-session may not be picked up by the *recipe* until recompile (export is unaffected — it reads the live asset).

**Manifest schema (`prop-manifest.json`, the contract for Phase 2/3):** `{ version, exportedAt, cellSize, defaultScale, brushes:[ { id,label,color,kind("object"|"ground"),groundTex,hasFootprint,footprint{x,z}, prefabs:[{name,path,x,z}] } ] }`. footprint = max over the brush's prefabs.

**Map JSON schema (painter output, Phase 2/3):** `{ version, name, cellSize, size{x,z}, ground:[{brush,cx,cz}], objects:[{brush,x,z,yaw,prefab}] }`. Grid mode: x,z = cell-centre world coords; free mode: raw world coords; yaw in degrees.

**Maintenance workflow (the whole point):** new asset → FbxPropExtractor makes the prefab → Brush Palette window → Auto-fill → Export Manifest (3 clicks). Painter reads brushes+sizes from the manifest, so new brushes/assets appear with no painter code change.

**ROUND-TRIP / SIDECAR EXPORT (2026-06-27, user's "edit a generated map" dream):** every `RecipeGenerator.Generate` now ALSO writes a painter-format **`<name>.map.json` sidecar** to **`tools/map-painter/exports/`** (outside Assets/ so Unity doesn't import it). Open it via the painter's **Import map…** → hand-edit → re-bake with `MapPainterImporter`. So generation is automatic, editing is a round-trip — no scene-scraper. New shared file **`Editor/MapSidecar.cs`**: schema DTOs + `ObjectFromWorld` (inverts the importer's centre-translate + z-flip + `forwardOffset`: `painterX=worldX+sizeX/2`, `painterZ=sizeZ/2−worldZ`, `yaw=worldYaw−forwardOffset`) + `RasterizeGround` (samples a `GroundSampler` per painter cell, inverting the cz flip, dominant channel→brush, grass omitted). RecipeGenerator captures every placed prop (incl. perimeter-wall pieces, brush≠reserved "wall"→"wall_pieces" so they re-import as exact objects not autotiled) into `_sidecarObjects` and rasterises ground from **the same** sampler the bake used — extracted as **`PxltgrGroundBlend.MakeProceduralSampler(seed,dirtAmount,paths,pathWidth,hardEdge)`** (LayPlot now just calls it) so sidecar ground == baked ground. **Known lossy bits (painter limits, documented):** no per-instance scale (re-import seats at palette `defaultScale`, scale-jitter dropped), no mob layer, no biome (mobs/biome aren't painter concepts). Compiled clean (force-refresh needed to import the new file).
